# Multimodal Claims Pipeline Playbook (Local Build)

## Overview

In this playbook, you will build a multimodal claim retrieval system designed for **insurance claim processors**. The goal is to enable fast and intelligent search for similar claims by combining image (X-rays), text (claim descriptions), and structured data (claim history, policy metadata).

This is a realistic enterprise-style project where you simulate a semantic layer across data modalities to power AI-assisted insurance claim review.

---

## Use Case

An **insurance claim processor** receives a new pet insurance claim:

- Description: "Persistent cough for 3 days"
- Attached X-ray image

They want to:

- Search across historical claims for similar symptoms and cases
- Retrieve previous outcomes, reimbursements, or treatments
- Reference linked structured data for policy context

This system supports text-image similarity search and structured data lookups through a cloud-native, modular setup.

---

## Architecture Overview

- **Image and Text Embeddings**: Extracted using a CLIP-based FastAPI service
- **Vector Database**: Weaviate (local container)
- **Metadata Store**: Structured CSVs (claim\_history, policy\_details)
- **Search UI**: Streamlit app to simulate the insurance claim search flow

---

## Prerequisites

- Python 3.10+
- Docker
- Weaviate (v3, local container)
- Virtual environment with the following installed:
  ```bash
  pip install fastapi uvicorn transformers pillow torch streamlit weaviate-client==3.26.7 pandas
  ```

---

## Step 1: Organize Sample Data

Create a local folder `data/` with the following:

```
data/
  PetPhotos/
  PetXrays/
  ClaimDescriptions/
  claim_history.csv
  policy_details.csv
```

- Each image/text file should include a `claim_id`
- `claim_history.csv` and `policy_details.csv` should include rows for each `claim_id` or `pet_id`

---

## Step 2: Start Weaviate Locally

```bash
docker run -d --name weaviate -p 8080:8080 semitechnologies/weaviate:1.23.9 \
  --env QUERY_DEFAULTS_LIMIT=25 \
  --env PERSISTENCE_DATA_PATH="/var/lib/weaviate" \
  --env AUTHENTICATION_ANONYMOUS_ACCESS_ENABLED=true \
  --env DEFAULT_VECTORIZER_MODULE=none \
  --restart unless-stopped
```

Verify it’s running:

```bash
docker ps
```

---

## Step 3: Create the CLIP Embedding API

File: `app.py`

This service accepts a claim description and optional image, and returns CLIP embeddings.

Run it with:

```bash
uvicorn app:app --host 0.0.0.0 --port 8001
```

---

## Step 4: Create Weaviate Schema

File: `weaviate_schema.py`

This creates a `ClaimDocument` class with fields:

- description (text)
- image (filename)
- claim\_id (string)
- metadata (JSON string containing structured info)

Run:

```bash
python weaviate_schema.py
```

---

## Step 5: Ingest All Claims

File: `store_with_embedding.py`

Loop over all files in `PetXrays` or `ClaimDescriptions`, send them to `app.py`, and store the embedding and associated metadata (from CSVs) in Weaviate.

This creates the searchable feature store.

---

## Step 6: Search by Description + Image

File: `search_similar_claims.py`

This takes a new claim (text + optional image), queries the embedding API, performs a vector search in Weaviate, and prints top 5 results with associated structured metadata.

---

## Step 7: Create a Demo App (Optional)

File: `demo.py`

A Streamlit-based UI that:

- Lets the processor type a symptom description and upload an image
- Returns the most similar past claims with structured data

Run:

```bash
streamlit run demo.py
```
